# Splunk Simple XML Dashboards — 2,500-Question MCQ Bank

## What this is

`questions.json` contains **2,500 multiple-choice questions** (four options, A–D, one correct
answer each) covering Splunk's **Simple XML dashboards** documentation — the classic
(non–Dashboard Studio) way of building Splunk dashboards and forms with XML source code.

The question set spans the full breadth of that documentation: dashboard and form structure,
every visualization type (tables, charts, maps, single values, gauges, trellis layout),
searches (inline, base, and post-process), drilldown and dashboard interactivity, tokens,
dashboard management and sharing, and the complete Simple XML / Event Handler / Chart
Configuration / Token reference pages.

## Origin

This question bank was generated by Claude (Anthropic), working directly from Splunk
Enterprise 10.4's official "Simple XML dashboards" manual at
`help.splunk.com` — every question is grounded in the actual documentation text for its
source page, not invented from general knowledge. Each question's source page is recorded in
its `source_url` field so it can be traced back to the exact manual page it came from.

### The original prompt

The task was kicked off with this instruction:

> Create a directory under splunk_app/splunkQuestions/ called xmlDashbordQuestions, then using
> this page, `https://help.splunk.com/en/splunk-enterprise/create-dashboards-and-reports/simple-xml-dashboards`
> and all the relevant subpages, generate 2500 multiple choice questions (four options for each
> question, A-D) based on the material in this document. Distribute the questions
> proportionately across topics based on the size of the topic in the manual.
>
> Ensure the output does not have answer length bias and the correct answer choice is dispersed
> across the four options.
>
> Output the questions in a JSON report in the same directory. Review the questions once
> complete and ensure there are no ambiguous questions and that all questions can be answered
> by a human or machine.
>
> Last, create a second document that provides statistics about the questions just created
> broken down by topic.
>
> Do this slowly, about 100 questions at a time. If you run out of capacity, stop and set a
> timer for 4 hours, then resume.

*(lightly copy-edited for typos and spacing; the substance is unchanged from the original. Note:
`xmlDashbordQuestions` is kept as spelled — that's the actual directory name the source files
were built in, so "correcting" it here would misrepresent the real path.)*

The build ran across several sessions (it hit usage limits partway through and was resumed
more than once), generating questions in batches of roughly 85–100, validating each batch
before merging it into the final set. After the full 2,500 were assembled, two further review
passes were done at the user's request:

1. A **duplicate/ambiguity spot-check** — a systematic near-duplicate sweep (beyond simple
   exact-text matching) caught questions that tested the identical fact twice with slightly
   different wording; these were rewritten with fresh facts from the same source pages.
2. A **documentation-dependency rework** — roughly 28% of questions were originally phrased
   as "per the documentation," "according to the documentation," or "what does the
   documentation say/recommend about X," which made them dependent on having read that exact
   page rather than testing standalone knowledge of the feature. These were reworded into
   direct, self-contained questions without changing the underlying fact, options, or correct
   answer.

Full details of both review passes are in `documentation_dependency_rework_report.md` in this
same directory.

### `questions.json` structure

Each entry is an object with these fields:

```json
{
  "id": "XMLQ-0001",
  "id_num": 1,
  "topic": "introduction",
  "subtopic": "introduction/getting-started",
  "source_url": "https://help.splunk.com/.../introduction/getting-started",
  "question": "Which source code format does the Splunk Dashboard Studio framework use for dashboard objects and the entire dashboard?",
  "options": {
    "A": "YAML-formatted manifests",
    "B": "HTML5 markup",
    "C": "Simple XML",
    "D": "JSON-formatted stanzas"
  },
  "correct_answer": "D",
  "explanation": "..."
}
```

- **`id`** — a unique, sequential identifier (`XMLQ-0001` through `XMLQ-2500`).
- **`topic`** / **`subtopic`** — the manual section and specific page the question is drawn
  from (14 topics, 60+ subtopic pages).
- **`source_url`** — the exact documentation page the question is grounded in.
- **`options`** — always exactly four (A–D); the correct answer is evenly distributed across
  all four positions (625 questions each), and option lengths were checked to avoid the
  "longest/shortest answer is usually correct" test-taking bias.
- **`explanation`** — a one-sentence justification citing the source fact.

## Possible uses

- **Splunk certification exam prep** — self-study quiz material for topics covered by Splunk's
  Power User / Admin dashboard-building content (Simple XML dashboards specifically).
- **Team onboarding / training** — a ready-made knowledge check for new hires or team members
  learning to build Splunk dashboards, or for validating skill level before/after an internal
  training session.
- **Quiz app or LMS content** — drop directly into a quiz platform, flashcard app (e.g. convert
  to Anki), or internal learning-management system; the JSON structure maps cleanly to most
  quiz-engine schemas.
- **Skills assessment** — a scored assessment for hiring, promotion readiness, or periodic
  recertification of Splunk dashboard skills on a team.
- **LLM/chatbot evaluation benchmark** — since every question has a single grounded correct
  answer with a source citation, this set can serve as an evaluation set for testing how well
  an AI assistant or search tool answers Splunk Simple XML questions.
- **Documentation gap-finding** — because the questions are exhaustively grounded in the
  manual, unusually hard-to-answer or awkwardly-testable questions can point to places where
  the underlying documentation itself is unclear or under-specified.
- **Trivia / gamified learning** — a large enough pool to power a recurring "Splunk dashboard
  trivia" feature (e.g., a Slack bot, internal wiki widget) without repeating questions for a
  long time.

## Caveats

- The question set is scoped entirely to **classic Simple XML dashboards**, not Dashboard
  Studio — a handful of questions mention Dashboard Studio only where the Simple XML docs
  themselves reference it (e.g., migration guidance).
- Some questions reference specific worked examples from the documentation (fictional data
  like "Buttercup Games" or "customer purchase" scenarios) — these test recall of the
  documentation's own examples rather than general Splunk knowledge, and are best used
  alongside the source material rather than as pure knowledge checks.
- This is a generated artifact, not an official Splunk product. It has been through automated
  and manual review passes (see `documentation_dependency_rework_report.md`), but has not been
  reviewed by Splunk or a subject-matter expert, and Splunk's documentation can change over
  versions (this set is based on the 10.4 manual).
